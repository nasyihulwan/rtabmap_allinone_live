## 3. Root cause KEDUA masalah + fix yang dikode

### (1) Cream/open_area masih terlewati — root cause: costmap gak tahu apa-apa soal scene_zone
`RoomZoneMap` (dipakai `object_goal_nav.py`) cuma PILIH TITIK GOAL yang di ruangan benar — path AKTUAL dari posisi robot ke titik itu dihitung `planner_server` (SmacPlanner2D) dari `global_costmap`, yang cuma tahu occupied/free/unknown dari lidar (`static_layer`, `/map` RTABMap). Costmap **sama sekali tidak tahu** soal kategori scene_zone — walau goal-nya sudah benar, jalur ke sana bisa tetap lewat cream.

**Fix — wiring `nav2_costmap_2d::KeepoutFilter` (sudah diriset viable sejak 2026-07-06, sekarang baru diimplementasi):**
- **File baru `semantic/scene_zone_to_keepout_mask.py`**: convert `scene_zone_final_v9_final.yaml/png` → mask format map_server (PGM+YAML). Walkable/FREE = `{corridor, doorway, staircase, workshop}` (label 1,3,4,6 — **doorway HARUS free** di sini, beda dari `room_zone_lookup.py` yang justru exclude doorway sbg batas ruangan). Keepout/OCCUPIED = `{unknown, open_area/cream, wall}` (label 0,2,5). Output: `output/scene_zone_test/keepout_mask.pgm/.yaml` (74.3% keepout dari total grid).
- **`config/nav2_params.yaml`**: plugin `keepout_filter` (`nav2_costmap_2d::KeepoutFilter`, `filter_info_topic: /keepout_filter_info`) ditambah ke `plugins` list KEDUA costmap (local+global), urutan sebelum `inflation_layer`.
- **`launch/nav2_husky.launch.py`**: 2 node baru DI DEPAN node_names list — `keepout_mask_server` (`nav2_map_server/map_server`, load `keepout_mask.yaml`, publish `/keepout_mask`) dan `costmap_filter_info_server` (publish `/keepout_filter_info`) — keduanya dimanage `lifecycle_manager_navigation` yang sudah ada.
- **Semua nama parameter diverifikasi presisi** (`filter_info_topic`, `mask_topic`, `type`, `base`, `multiplier`, `yaml_filename`, `topic_name`, `frame_id`) via `strings` langsung terhadap binary terinstall (`libmap_server_core.so`, `libfilters.so`) — bukan tebakan dari dokumentasi/memori.

### (2) Path masih mepet tembok — root cause: `inflation_radius` kegedean kecil
`inflation_radius` cuma **0.50m**, sementara `robot_radius=0.38m` — cost gradient cuma efektif ~0.12m di luar body robot. Di ruangan lebar, gradient sudah nol jauh sebelum ke tengah ruangan, jadi planner gak ada insentif jauhi tembok begitu lewat radius sekecil itu. **Dicek juga:** custom BT dengan `smoother_server`/`SmoothPath` SUDAH DIMATIKAN sejak 2026-07-08 (bug extrapolation error) — live path SEKARANG murni raw output SmacPlanner2D, jadi smoother_server BUKAN penyebab (sempat dicurigai duluan, ternyata bukan).

**Fix:** `inflation_radius` 0.50→**0.85m** (local+global costmap) — kasih ~0.47m gradient efektif, cukup dorong path ke tengah tanpa (harusnya) nutup doorway tersempit (min doorway ~1.2m vs robot diameter 0.76m, masih ada slack). **BELUM divalidasi live** — kalau planner tiba-tiba gagal cari path di goal yang sebelumnya jalan, ini kandidat pertama dicurigai.
